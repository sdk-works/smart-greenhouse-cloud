# 环境控制实现状态与下一步

更新时间：2026-08-25

## 已完成（代码层）

- 风机/水阀设备查询、档案配置、人工命令、紧急关阀、命令记录接口。
- 命令持久化、权限控制、审计日志、安全参数校验。
- MQTT 命令下发及 `command_ack`/`device_status` 入库。
- 前端“环境控制”入口和命令状态展示。
- 自动规则的数据结构及禁用态保存接口。
- 后端 Python 编译检查、前端生产构建通过。

## 未完成（必须现场或控制器配合）

- 真实风机、水阀控制器的 MQTT 网关程序及电气接线验证。
- 开/关反馈、故障反馈、断线行为、掉电默认状态测试。
- 自动规则执行器、持续时间判定、防抖、冷却期和规则冲突仲裁。
- 缺水、超压、漏水、急停、消防等硬件联锁；这些必须优先在本地控制层实现。
- 24 小时稳定性和断网恢复测试。

## 推荐实施顺序

1. 确认每台设备的编号、区域、常态安全位置、控制与反馈点位。
2. 编写/接入现场网关，完成 MQTT 回执模拟测试。
3. 单设备低风险点动：先关命令，再 3 秒启动，再自动关闭。
4. 验证急停、通信中断、重启、重复命令和过期命令。
5. 通过人工控制验收后，再启用一条低风险自动规则进行灰度测试。

## 部署

1. 备份数据库和当前 `/opt/greenhouse`、`/var/www/greenhouse`。
2. 执行 `psql "$DATABASE_URL" -f backend/migrations/20260825_add_control_v1.sql`。
3. 更新后端并重启服务，确认 `/api/v1/controls/actuators` 返回正常。
4. 部署 `frontend/build` 后打开“环境控制”。
5. 没有真实设备回执时，命令停留在 `sent` 属于正常现象，不能人工改为 `executed`。
