# DTU可靠上传联调版 2026-09-03

## 范围
云端运行于虚拟机192.168.109.128；采集候选版在旧工控机192.168.0.139。
只修改DTU通信和上传队列。没有启动相机、导航、机械臂或风机/阀门控制。
COM1=/dev/ttyS0，9600/8N1，RS232；DTU保留200ms/1024Bytes。

## 已实现
- DTU专用上行：一行一个dtu-v1封装，最大含换行8192字节；UTF8字节缓存，支持拆包和合包。
- body沿用业务JSON；msg_id稳定，sha256校验完整性（不是加密或身份认证）。
- 默认仅ROB001上行使用流式解析，可由DTU_ROBOT_IDS配置；其他设备保留原MQTT路径。
- 同一DTU流按顺序处理；残缺帧20秒超时，下次收到数据时判定，丢弃至换行恢复；超长同样丢弃。
- ROB001无残缺缓冲时兼容旧完整JSON MQTT消息；禁止两种发送端混用同一个DTU身份。
- 确认型消息仅支持telemetry和link_test。前者遥测和收据在同一数据库事务提交；后者仅写诊断收据。
- dtu_receipts以(robot_id,msg_id)为主键，事务锁保证并发去重；同编号不同内容拒绝。
- 云端提交后向agri/robot/ROB001/config回复upload_ack（非控制指令），retain=false。
- 工控机校验robot_id/msg_id/sha256/status，确认后才标记uploaded。
- 串口单一拥有者，断开或确认超时关闭句柄，下次重试重新打开。
- SQLite作为上传队列，分批扫描；失败按2～30秒退避；程序重启读取待上传记录。
- 下行仅接受匹配ACK；非ACK消息记录并忽略，不执行配置或控制。

- 分帧单测5项：逐字节/中文/多种长度/100条合并/超时/超长/校验/长度限制。
- 云端100条自动测试：任意731字节边界拆分、重组、数据库去重、新服务实例重复确认、内容冲突拒绝。

- 实际COM1→DTU→花生壳→虚拟机→ACK：pad为10/500/1200/2500字节的4条消息均通过；最后一条重发通过。
- 测试数据type=link_test，未写入真实遥测表。诊断收据保留便于追溯。
