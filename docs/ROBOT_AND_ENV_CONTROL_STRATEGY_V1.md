# 巡检机器人与大棚环境控制策略 V1.0

状态：正式设计基线  
日期：2026-08-24  
适用范围：巡检机器人、风机、水阀、云端平台、第三方导航及后续边缘控制器。

## 1. 设计目标

系统采用“巡检与控制分离”的总体原则：

- 巡检机器人负责移动、定点采样、拍照、本地保存和数据上报。
- 云端负责数据校验、规则计算、控制决策、命令下发、执行确认和审计。
- 风机、水阀等执行设备只执行经过权限、安全联锁和有效期校验的命令。
- AI 在 V1 阶段只生成分析、建议和告警，不直接绕过规则引擎控制设备。

## 2. 系统职责边界

### 2.1 巡检机器人

机器人必须完成：

1. 接收第三方导航到点消息。
2. 校验任务ID、点位和采集时长。
3. 检查传感器、相机及机械机构状态。
4. 采集土壤水分、土温、EC、pH、氮、磷、钾。
5. 按配置拍摄巡检图片。
6. 先保存本地，再加入云端上传队列。
7. 断网时继续保存，恢复网络后自动补传。
8. 设备归位或无机械臂模式完成采集后，向导航返回完成状态。

机器人禁止：

- 根据单次测量自行开启风机或水阀。
- 绕过云端安全联锁直接控制环境设备。
- 在数据尚未本地可靠保存时返回任务完成。

### 2.2 云端平台

云端必须完成：

1. 校验机器人、点位、时间戳、消息ID和数据质量。
2. 保存原始数据、汇总数据、图片及任务记录。
3. 根据设备模式和规则生成控制决策。
4. 下发带唯一命令ID、原因、有效期和安全限制的控制命令。
5. 等待设备确认，不能以“MQTT发布成功”代替“设备执行成功”。
6. 保存控制前数据、决策过程、命令、确认和控制后数据。
7. 提供人工接管、维护锁定、紧急停止和告警处理。

### 2.3 风机和水阀控制器

执行控制器必须：

- 支持本地安全逻辑，云端断线时仍能执行超时关闭。
- 校验命令ID、设备ID、动作、有效期和参数范围。
- 对重复命令保持幂等，不重复执行同一 `command_id`。
- 回复接收、执行中、执行成功、拒绝、超时或失败状态。
- 定时上报实际开关状态、故障码和最后通信时间。

## 3. 巡检任务状态机

标准状态：

```text
IDLE
  → RECEIVED
  → NAVIGATING
  → ARRIVED
  → PRECHECK
  → [DEPLOY]
  → [STABILIZE]
  → SAMPLING
  → CAPTURING
  → [RETRACT]
  → LOCAL_SAVED
  → UPLOAD_PENDING / UPLOADED
  → DONE
  → IDLE
```

方括号状态只在对应硬件启用时存在。任何关键步骤失败进入 `FAULT`。

### 3.1 到点串口协议

```text
ARR|{task_id}|{point_code}|{sample_seconds}\n
```

机器人回复：

```text
ACK|{task_id}\n
RUNNING|{task_id}|state={state}\n
DONE|{task_id}|saved=1|upload={uploaded|pending}\n
FAULT|{task_id}|{error_code}\n
BUSY|{task_id}|active={active_task_id}\n
```

### 3.2 任务幂等

- `task_id` 在机器人任务库中唯一。
- 已完成任务再次到达时只回复 `DONE|duplicate=1`，不重复采集。
- 故障任务默认不自动重做，由导航或云端生成新的任务ID。
- 旧版 `arr01|` 兼容格式只用于测试，不允许用于正式巡检。

## 4. 采集与数据质量策略

### 4.1 默认参数

| 参数 | 默认值 | 可配置范围 |
|---|---:|---:|
| 采集时间 | 10秒 | 1～120秒 |
| 采样周期 | 1秒 | 0.5～5秒 |
| 最少有效样本 | 5个 | 3～30个 |
| 传感器稳定时间 | 3秒 | 0～30秒 |
| 单任务总超时 | 180秒 | 30～600秒 |

### 4.2 汇总方法

每个参数保存：

- 平均值 `mean`
- 中位数 `median`
- 最小值 `min`
- 最大值 `max`
- 有效样本数 `sample_count`

云端主数据使用有效样本平均值，完整逐次采样保留在工控机本地任务库。

### 4.3 数据有效性

数据用于自动控制前必须满足：

- 机器人已注册且处于启用状态。
- `msg_id`、`task_id`、时间戳和点位映射完整。
- `msg_id` 未被处理过。
- 数据时间未超过规则配置的有效期。
- 有效样本数达到最低要求。
- 数值在传感器量程和现场合理范围内。
- 点位与灌溉区域、设备绑定关系有效。

任一条件不满足时，数据仍可存档，但不得触发自动控制。

## 5. 环境设备模型

每台设备至少包含：

```text
device_id
device_type: fan / water_valve
greenhouse_id
zone_id
control_mode: manual / auto / maintenance
desired_state
actual_state
online_status
fault_code
last_seen
last_command_id
capabilities
safety_limits
```

### 5.1 设备状态

```text
OFFLINE
IDLE
STARTING
RUNNING
STOPPING
FAULT
MAINTENANCE
EMERGENCY_STOP
```

`desired_state` 和 `actual_state` 必须分开保存，避免把已下发命令误认为实际状态。

## 6. 控制模式和优先级

### 6.1 控制模式

- `manual`：有权限的用户直接控制，自动规则暂停。
- `auto`：云端规则引擎可以生成并执行控制命令。
- `maintenance`：自动控制禁止，仅维护人员可进行受限测试。

### 6.2 优先级

```text
紧急停止
  > 本地硬件保护
  > 维护锁定
  > 人工手动命令
  > 自动安全规则
  > 普通自动规则
  > 定时任务
  > AI建议
```

高优先级状态未解除时，低优先级命令必须被拒绝并记录原因。

## 7. 风机控制策略

### 7.1 默认规则

```text
温度 ≥ 32℃，持续2分钟 → 启动风机
温度 ≤ 29℃，持续5分钟 → 关闭风机

空气湿度 ≥ 90%，持续3分钟 → 启动风机
空气湿度 ≤ 82%，持续5分钟 → 关闭风机
```

阈值必须按大棚、作物和生长阶段独立配置。

### 7.2 风机安全限制

- 最短运行时间：3分钟。
- 最短停机时间：2分钟。
- 单次最长连续运行：30分钟。
- 最大命令重试：2次。
- 多风机启动间隔：默认5秒。
- 连续执行失败后锁定为 `FAULT`，禁止无限重试。
- 本地控制器必须支持最大运行时间到期自动停止。

### 7.3 多级控制

设备支持档位时：

- 轻度超限：低速。
- 中度超限：中速。
- 严重超限：高速。
- 降档和关闭必须使用迟滞区间，避免频繁切换。

## 8. 水阀控制策略

### 8.1 点位与区域关系

```text
机器人点位 → 大棚点位 → 灌溉区域 → 水阀
```

禁止使用一个点位的数据控制整个大棚，除非该大棚明确配置为单区域。

### 8.2 默认规则

```text
土壤水分低于下限
且连续两次有效巡检均偏低
且两次数据来自同一区域
且没有灌溉锁定
→ 打开对应水阀60秒
→ 到期强制关闭
→ 进入10分钟观察期
```

观察期结束后等待复测，不允许立即连续灌溉。

### 8.3 水阀安全限制

- 单次最大开启时间。
- 每小时最大累计开启时间。
- 每天最大累计灌溉量或时长。
- 两次灌溉最短间隔。
- 开阀后必须收到实际状态反馈。
- 命令过期、数据过期、点位错误或传感器异常时禁止开阀。
- 云端失联时本地控制器必须按命令最大时长自动关阀。
- 提供“一键关闭全部水阀”，不提供“一键打开全部水阀”。

接入流量计后，灌溉策略从时间控制升级为流量闭环，并增加无流量、流量过大和疑似漏水告警。

## 9. 自动控制规则状态机

```text
DISABLED
  → MONITORING
  → CONDITION_PENDING
  → READY
  → COMMAND_SENT
  → ACKNOWLEDGED
  → EXECUTING
  → VERIFYING
  → COMPLETED
```

异常分支：

```text
REJECTED / TIMEOUT / FAILED / SAFETY_LOCKED
```

一次规则触发必须生成唯一 `decision_id`，相关命令使用唯一 `command_id`。

## 10. MQTT协议

### 10.1 Topic

```text
设备上行：agri/device/{device_id}/up
设备命令：agri/device/{device_id}/command
设备配置：agri/device/{device_id}/config
机器人上行：agri/robot/{robot_id}/up
```

命令和确认使用 QoS 1。设备端必须通过 `command_id` 保证幂等。

### 10.2 控制命令

```json
{
  "type": "command",
  "command_id": "CMD-20260824-001",
  "decision_id": "DEC-20260824-001",
  "device_id": "FAN001",
  "action": "turn_on",
  "params": {
    "duration_seconds": 300,
    "level": 2
  },
  "source": "auto_rule",
  "reason": "temperature_high",
  "issued_at": "2026-08-24T10:00:00Z",
  "expires_at": "2026-08-24T10:00:30Z"
}
```

### 10.3 执行确认

```json
{
  "type": "command_ack",
  "command_id": "CMD-20260824-001",
  "device_id": "FAN001",
  "status": "executed",
  "actual_state": "on",
  "fault_code": null,
  "timestamp": "2026-08-24T10:00:02Z"
}
```

确认状态：

```text
accepted / executing / executed / rejected / timeout / failed
```

## 11. 超时与重试

默认策略：

1. 命令下发后3秒内等待 `accepted`。
2. 未确认时使用同一 `command_id` 重发，最多2次。
3. 设备执行完成后必须上报 `actual_state`。
4. 风机或水阀的停止命令优先于启动命令。
5. 关闭命令失败时立即产生高等级告警。
6. 水阀关闭失败时触发本地硬件超时保护，并通知人工现场检查。

## 12. 权限与审计

### 12.1 权限

- 查看者：只读。
- 操作员：手动控制已授权区域设备，不能修改安全上限。
- 管理员：配置自动规则、设备绑定和控制模式。
- 超级管理员：修改系统级安全限制和紧急策略。

### 12.2 审计记录

每次控制保存：

- 操作人或规则ID。
- 决策ID和命令ID。
- 控制原因。
- 控制前传感器快照。
- 目标状态和实际状态。
- 下发、确认、完成时间。
- 重试次数和失败原因。
- 人工接管、取消或紧急停止记录。

## 13. 告警分级

### 一级：紧急

- 水阀无法关闭。
- 漏水或异常持续流量。
- 设备急停。
- 电气或控制器严重故障。

### 二级：重要

- 命令多次无确认。
- 风机连续运行超时。
- 传感器连续异常。
- 机器人关键任务失败。

### 三级：提示

- 数据暂时过期。
- 单次采样不足。
- 设备短时离线后恢复。

## 14. AI使用边界

V1阶段AI可以：

- 分析趋势和异常。
- 生成控制建议及原因。
- 建议阈值调整。
- 生成巡检和控制报告。

V1阶段AI不可以：

- 绕过规则引擎直接下发命令。
- 修改紧急停止和本地硬件保护。
- 在缺少有效数据时自动开启水阀。
- 自动扩大设备控制权限或区域范围。

## 15. V1实施阶段

### 阶段A：设备基础控制

- 注册风机和水阀。
- 完成设备状态上报。
- 完成手动开关、定时关闭和命令确认。
- 完成权限、审计和紧急关闭。

### 阶段B：规则控制

- 温湿度控制风机。
- 土壤水分控制区域水阀。
- 实现迟滞、持续时间、冷却时间和每日上限。
- 实现失败重试、故障锁定和告警。

### 阶段C：巡检联动

- 巡检任务与点位、区域、设备绑定。
- 采集数据质量判定。
- 控制前后数据形成完整因果链。
- 图片、任务和控制记录统一关联。

### 阶段D：AI辅助

- 趋势预测。
- 异常诊断。
- 控制建议。
- 人工确认后执行建议。

## 16. V1验收标准

- 机器人断网采集不丢失，恢复后自动补传。
- 同一任务和消息不会重复执行或重复入库。
- 风机、水阀手动控制均有执行确认。
- 水阀在云端断网时仍能按最大时长关闭。
- 自动规则具有迟滞、持续时间和冷却时间。
- 数据无效或过期时不会触发自动控制。
- 所有控制操作可追溯到用户或规则。
- 紧急停止优先级最高且不能被自动规则覆盖。
- 任意控制失败都有明确状态和告警。
- 云端重启后任务、命令和登录状态可恢复。
