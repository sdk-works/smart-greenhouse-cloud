## 3. `keepalive=0` 为什么会造出"假在线"

1. MQTT 的 keepalive 是**客户端声明**的心跳周期。设备 CONNECT 时填 `0`，语义是"**不启用心跳**"。
2. EMQX 因此：既不向设备发 `PINGREQ`，也不期望设备发 `PINGREQ`，**永远不会**因空闲判定该连接超时（默认 15s 超时规则对 keepalive=0 的会话不生效）。
3. 于是连接的存活只剩 TCP 层。而 TCP **只有在有数据要发时才会发现对端消失**：
   - 08:54:19 云端发完最后一条 ACK，`bytes_acked == bytes_sent`，`Send-Q=0` → 对端当时**确实还在 ACK**；
   - 08:55:18 之后云端**没有任何要发的东西**（ACK 只在收到上行时才产生），也就**没有任何写操作会失败**；
   - Linux 默认 `tcp_keepalive_time=7200s` 且看起来未启用 SO_KEEPALIVE（15 小时未断），TCP 层也不会主动探测。
4. 结果：**"connected=true" 只代表"EMQX 没收到过 FIN/RST"，不代表设备还活着**。
   设备掉电时 TCP 来不及发 FIN，连接就会像这样永远挂着。

> 判据：`bytes_sent == bytes_acked && Send-Q == 0` 只能说明"截至最后一次交互对端还 ACK 过"，
> **不能**证明现在还活着。要证明活着，必须有持续的**上行**数据或显式心跳。
